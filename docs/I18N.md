# Internationalization (i18n) Strategy

## Current State

### Content Model

All content types include a `locale` field (default `"en"`):

- `Page.locale` — indexed
- `Blog.locale` — indexed
- `Menu.locale`

This allows storing multiple translations of the same content as separate documents differentiated by locale.

### Direction

The theme config stores a global `direction` (`"ltr"` or `"rtl"`) and a `defaultLocale` (e.g. `"en"`, `"ar"`). These are applied to the `<html>` element:

```html
<html lang="ar" dir="rtl">
```

CSS uses logical properties (`margin-inline`, `padding-inline`, `inset-inline-start`, `border-block-*`) so layouts adapt automatically when direction is switched to RTL.

### RTL Support

- Global direction toggle in the theme editor
- CSS logical properties throughout `globals.css` and components
- RTL-friendly Google Fonts included in the font catalog (Noto Sans Arabic, Cairo, Tajawal)

## URL Strategy (Future)

The recommended approach for per-locale routing is path-based:

```
/en/about   → Page { slug: "about", locale: "en" }
/ar/about   → Page { slug: "about", locale: "ar" }
/en/blog/my-post → Blog { slug: "my-post", locale: "en" }
```

To implement:

1. Add a `[locale]` dynamic segment as a route group: `app/[locale]/[slug]/page.js`
2. Query content by both `slug` and `locale`
3. Add a locale switcher component that links to the same slug in a different locale
4. Use Next.js `generateStaticParams` to enumerate locales

### Locale Switcher

A locale switcher would render links to alternate locale versions of the current page. It can derive available locales from the published content (e.g. find all Pages with the same slug but different locales).

### Fallback

If a page does not exist in the requested locale, fall back to the `defaultLocale` from the theme config. If neither exists, return 404.

## Migration Path

The current single-locale setup works for sites in one language. To add multi-locale support:

1. Create locale-prefixed route groups (`app/[locale]/...`)
2. Update middleware to detect/redirect locale
3. Update `generateMetadata` to include `alternates.languages` for SEO
4. Add a locale switcher to `PublicShell`
5. Update `sitemap.js` to include locale-specific URLs
